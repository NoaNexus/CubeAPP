# 07. 开源合规与离线分发

> 本文是项目工程合规方案，不替代针对具体争议的法律意见。

## 1. 决策

如果项目复制、翻译或改编 csTimer / Twisty Timer 的代码，或直接带入其具有表达性的公式数据集，最终组合应用按 GPL-3.0-only 分发。

选择 only 而不是 or-later 是保守处理：上游仓库明确标示 GPL-3.0，但在没有逐文件确认“or later”授权前，不额外扩大许可证版本。

如果最终完全不复制 GPL 内容，只独立实现协议并使用 MIT / MPL 依赖，理论上可以选择更宽松许可证；但这会增加逐文件溯源和“是否构成改编”的判断成本。对自用和几十人分享，统一 GPL-3.0-only 更省心。

## 2. 小范围分享的实际义务

把 APK 发给朋友属于分发。最简单的合规方式是同一分享位置同时提供：

- 同版本签名 APK。
- 完整对应源码。
- 构建脚本、依赖锁定和生成 APK 所需文件。
- GPL-3.0 完整许可证。
- 第三方许可证和版权通知。
- 修改说明和版本号。

不要求：

- 必须上架应用商店。
- 必须向全世界公开仓库。
- 必须给没有收到 APK 的人提供源码。
- 必须提供服务器，因为本项目本来就没有服务器。

收到 APK 的人必须能获得 GPL 赋予的查看、修改和再分发权。不能用聊天口头约定禁止朋友再分享开源代码。

## 3. 推荐仓库许可证结构

    LICENSE
    LICENSES/
      GPL-3.0-only.txt
      MPL-2.0.txt
      MIT.txt
      OFL-1.1.txt
    NOTICE.md
    THIRD_PARTY_NOTICES.md
    SOURCE.md
    CHANGELOG.md
    docs/
      provenance/
        formulas.yml
        protocol.md

源码文件使用 SPDX 标识：

    SPDX-License-Identifier: GPL-3.0-only

从上游复制或修改的文件保留原版权头和许可证，不把自己的版权覆盖在原作者之上。修改处在 git 历史和 NOTICE 中说明。

## 4. 第三方组件策略

| 组件 | 已知许可证 | 使用方式 | 项目动作 |
|---|---|---|---|
| csTimer | GPL-3.0 | 协议、计时与算法研究；若复制则进入 GPL 组合 | 固定 commit，保留 LICENSE、版权和修改记录 |
| Twisty Timer | GPL-3.0 | 公式库和 Android 体验参考；若复制数据或代码则进入 GPL 组合 | 固定 commit，记录具体文件和变化 |
| cubing.js | MPL-2.0 | 尽量作为未修改、独立打包的本地渲染依赖 | 保留 MPL 文件、源码地址和版本；修改其文件时公开对应修改源码 |
| smartcube-web-bluetooth | MIT | V10 同族协议和 gyro 解析参考 | 保留 MIT notice 和作者信息；核对其中各协议文件的来源说明 |
| AndroidX / Kotlin | Apache-2.0 等 | 正常依赖 | 自动生成第三方清单并保留通知 |
| Noto Sans SC | OFL-1.1 | 字体 | 保留 OFL，遵守 Reserved Font Name 规则 |
| Barlow Condensed | OFL-1.1 | 数字字体 | 保留 OFL |
| JetBrains Mono | OFL-1.1 | 公式字体 | 保留 OFL |

注意：一个仓库整体标 MIT，不代表其中改编自 GPL 项目的具体文件必然可以忽略原来源。协议移植时要读文件头、提交历史和说明。由于本应用统一 GPL，这个兼容风险更容易处理，但署名和来源仍必须保留。

## 5. 公式与数据的来源

魔方转动序列和 case 的事实部分可能具有较弱或不确定的版权属性，但整理方式、命名、选择、注释、配图和完整数据集合可能受到保护。项目不依赖“公式肯定没有版权”这一判断。

采用以下来源账本：

| 字段 | 示例 |
|---|---|
| stableId | cfop.oll.21 |
| 内容类型 | case state / algorithm / note / image |
| 来源项目或人工录入 | Twisty Timer 或 self-curated |
| 来源版本 | commit hash |
| 原许可证 | GPL-3.0 |
| 是否改写 | 是 / 否 |
| 验证方式 | 引擎校验 + 人工实拧 |
| 首次进入版本 | preset 1.0.0 |

预设图由应用根据状态生成。不要：

- 裁切用户提供的 GAN 教程海报。
- 抽取 Bilibili 视频帧作为 UI 素材。
- 复制魔小库、Smart Player Pro 或厂商 APP 的图标、页面或品牌。
- 把 GAN、魔域、csTimer 等名称放入 APP 名称，造成官方合作印象。

可以：

- 用这些产品作为功能与信息架构参考。
- 在“支持设备”中以事实方式写“魔域威龙 V10 AI”。
- 在第三方通知和协议来源中准确署名。

## 6. cubing.js 的处理

建议：

- 固定一个经过测试的版本。
- 不修改 vendor 源码，所有主题和消息适配放在项目自己的 wrapper 文件。
- 把实际打包的 JS、其版本、上游源码链接和 MPL-2.0 文本收入源码包。
- 若修改 MPL 覆盖的源文件，公布这些修改后的文件及其 MPL 权利，不把它们改标为纯 GPL。
- WebView 只加载本地构建产物，不从 CDN 下载。

组合应用可以统一说明为 GPL-3.0-only，同时逐组件保留 MPL 的文件级条件。

## 7. 发布包

每次分享生成一个不可混淆的目录：

    CubeTrace-0.1.0/
      CubeTrace-0.1.0-release.apk
      CubeTrace-0.1.0-source.zip
      SHA256SUMS.txt
      RELEASE_NOTES.md
      INSTALL.md

source.zip 至少含：

- 所有 Kotlin、Gradle、JavaScript、样式和公式源数据。
- Gradle wrapper 与版本目录。
- 生成的依赖清单。
- 构建与签名之外的复现说明。
- LICENSE、NOTICE、THIRD_PARTY_NOTICES 和 SOURCE。
- 对应 git commit。

不得把签名私钥、个人 local.properties、设备地址、调试日志或备份数据放进源码包。

## 8. SOURCE 页面最少内容

应用“设置 → 关于 → 获取源码”显示：

- 当前 APP 版本和 commit。
- 本程序是自由软件，许可证为 GPL-3.0-only。
- 与本 APK 完全对应的源码获取位置。
- 如果采用离线分享，显示同一压缩包中的源码文件名和 SHA-256。
- 第三方通知入口。

如果使用临时网盘或私人仓库，至少在该 APK 的朋友使用期间保持可访问。更稳妥的是 APK 与源码始终一起打包。

## 9. 签名与升级

- 创建独立 release keystore，不与其他 APP 共用。
- keystore、alias、恢复说明做两份离线加密备份。
- 密码放密码管理器，不写入仓库或聊天记录。
- applicationId 首次分享后保持不变。
- versionCode 单调递增。
- 发布前验证旧版本覆盖安装和数据库迁移。
- 丢失签名密钥意味着朋友不能直接覆盖升级，只能卸载重装并从备份恢复。

## 10. 隐私与分发说明

虽然完全离线，仍应提供一页简短隐私说明：

- 不创建账号。
- 不访问互联网。
- 不上传成绩、公式、蓝牙地址或诊断数据。
- 蓝牙权限只用于连接用户选择的智能魔方。
- 备份和诊断文件由用户主动选择保存或发送。

诊断包默认移除：

- 完整蓝牙 MAC。
- 用户笔记。
- 不相关附近设备。
- 历史成绩详情，除非用户明确勾选。

## 11. 发布前合规检查

- [ ] 仓库根目录存在 GPL-3.0-only 许可证。
- [ ] 每个自有源文件有正确 SPDX。
- [ ] 复制或修改的上游文件保留版权头。
- [ ] 所有依赖有名称、版本、源码链接和许可证。
- [ ] 公式来源账本覆盖 119 个 case。
- [ ] 未包含参考海报、视频帧或其他 APP 资产。
- [ ] APK 中的“关于”能看到许可证和源码位置。
- [ ] APK 与 source.zip 指向同一 commit。
- [ ] source.zip 能在干净环境按说明构建。
- [ ] SHA-256 已生成并核对。
- [ ] 签名密钥不在发布包。
- [ ] 隐私说明与实际权限清单一致。

## 12. 如果决定完全不碰 GPL

需要同时满足：

- 不复制 csTimer / Twisty Timer 代码。
- 不直接复制其成套公式数据、注释、名称或素材。
- V10 协议按公开事实和独立测试重新实现，或只移植许可证清晰的 MIT 实现并保留 notice。
- 依赖审计确认没有 GPL 传递组件。
- 重新选择并记录项目许可证。

这条路线不一定更省时间。对本项目当前用途，保持 GPL-3.0-only 是推荐基线。

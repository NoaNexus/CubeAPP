# 10. 智能成绩分析、CFOP 提速诊断与纪录规划

> 文档状态：实施规划基线
> 文档版本：1.1
> 调研日期：2026-08-19
> 适用范围：3×3 CFOP、魔域 V10 AI、完全离线 Android APP
> 依赖规范：01、02、04、05、06、08
> 补充规范：11（赛前/赛后反馈位置与当前水平估计）

## 1. 目的

本规范补足两组后续能力：

1. 将智能魔方 Solve 拆成 `C / F1 / F2 / F3 / F4 / O / P`，输出总用时、各部分用时、TPS、停顿率、步数、转体和可解释的提速建议。
2. 建立类似成熟计时器的成绩记录体系，包含 current / best single、ao5、ao12、趋势、PB 提醒，以及“下一把达到多少可以刷新纪录”的精确计算。

本文件扩展 06 文档第 9–15 节。若两者冲突，以更具体且版本更新的本文件为准；底层事实仍以原始 MoveEvent、CubeState 和单调时间为准。

### 2.2 产品机会

公开产品普遍能给出大量数据，但“为什么慢、下一步练什么”常常不够透明。本项目的差异化不是制造一个不可解释的综合分，而是把每条建议拆成：

- 观察到的指标。
- 对比基线和样本范围。
- 对应的时间区间或 Move Rail 位置。
- 建议训练动作。
- 置信度与限制。

## 3. 产品原则

1. **先事实，后判断**：Move、时间、局面和断连是事实；阶段名、停顿和建议是可重算分析。
2. **单次与趋势分开**：单次只描述这一次；至少 12 个完整样本后才生成趋势建议。
3. **个人基线优先**：默认与用户最近的自己比较，不用职业选手阈值羞辱用户。
4. **不把推断写成事实**：可以说“F2 前有 0.82 秒无 move”，不直接说“你没有观察下一对”。
5. **一次只突出一个主建议**：最多一个首要建议和两个次要建议。
6. **所有结果可追溯**：点击指标或建议可以定位到 Move Rail 和三维回放。
7. **数据不完整就降级**：跨越序号 gap 的阶段不输出伪精确 TPS 或停顿率。
8. **成绩与分析解耦**：手动计时也进入记录统计；只有带完整 move 的 Solve 才进入 CFOP 深度分析。

## 5. `C / F1 / F2 / F3 / F4 / O / P` 分段

### 5.1 含义

| 代码 | 起点 | 终点 | 边界动作归属 |
|---|---|---|---|
| C | 第一真实 move / Solve 开始 | Cross 稳定完成 | 完成 Cross 的 move 属于 C |
| F1 | Cross 完成 | 第一对 F2L pair 稳定完成 | 完成该 pair 的 move 属于 F1 |
| F2 | F1 完成 | 第二对稳定完成 | 属于 F2 |
| F3 | F2 完成 | 第三对稳定完成 | 属于 F3 |
| F4 | F3 完成 | F2L 全部稳定完成 | 属于 F4 |
| O | F2L 完成 | Last Layer 稳定定向 | 完成 OLL 的 move 属于 O |
| P | OLL 完成 | CubeSolved，默认含 AUF | 完成复原的 move 属于 P |

阶段时间使用单调时间；七段相加必须等于 raw Solve time，允许因纳秒到毫秒显示取整出现不超过 1 ms 的视觉差。

### 5.2 F1–F4 不是固定槽位

- F1–F4 表示本次 Solve 中按时间先后稳定完成的第 1–4 对。
- 同时保存实际 slot：FR / FL / BR / BL，以及对应 corner / edge 身份。
- UI 主列显示 F1–F4，展开后显示“F2 · BR 槽”。
- 不根据转体后的画面位置猜 slot；以规范中心坐标和 cubie 身份判断。

### 5.3 稳定 pair 完成

某 slot 的稳定完成点是：

> 从该 move 后，此 corner + edge 位于正确槽位和方向，并一直保持到 F2L 完成的最早 move。

先完成后又被破坏的 pair 不立即形成最终 F1–F4 边界，而记录：

- `PAIR_TEMP_SOLVED`。
- `PAIR_REGRESSION`。
- 最终稳定完成 ordinal。

这样不会把一次试插或误破坏误判成两个阶段。

### 5.4 X-cross 与同时完成

- Cross 完成时已有 `k` 对稳定 pair：标记 `initialPairs=k`。
- 对应 F1…Fk 显示 `0.000 s · 随 Cross 完成`，不从 C 中重复扣时间和 move。
- 若一个 move 同时使两对稳定完成，两条边界可使用相同时间；后一段时长为 0，并标“同一步完成”。
- 确定同时间 pair 的显示顺序使用稳定 slot key，仅为展示，不宣称用户意图。

### 5.5 Skip 与异常

- OLL skip：O=0，显示“跳 OLL”。
- PLL skip：P=0，显示“跳 PLL”；若仍有 AUF，则 AUF 默认计入 P，不算纯 PLL skip。
- gap 跨阶段边界：边界显示区间和低置信度；受影响阶段精确指标隐藏。
- 用户修正边界：保留自动值、人工值和原因，指标按人工值重算并标注。

## 6. 指标定义

### 6.1 总用时与部分用时

- `rawSolveMs = solvedAt - firstMoveAt`。
- `finalResult` 用于排名：NONE 为 raw，PLUS_TWO 为 raw+2000，DNF 无有效排名值。
- CFOP 分析一律使用 raw 时间；惩罚单独展示，不污染阶段用时。
- `phaseShare = phaseDuration / rawSolveDuration`。

### 6.2 Move count

- 主口径沿用用户设置，默认 HTM。
- 每个阶段保存 HTM / QTM / STM 三套可重算值，UI 默认只显示一套。
- 整体转体不计入 HTM/QTM，但单独显示 rotation count。
- 完成阶段的边界 move 计入结束阶段，避免重复或漏计。

### 6.3 总 TPS 与部分 TPS

主指标：

```text
phaseTotalTps = phaseMoveCount / phaseDurationSeconds
solveTotalTps = solveMoveCount / rawSolveSeconds
```

辅助指标：

```text
phaseActiveSeconds = phaseDurationSeconds - phasePauseSeconds
phaseActiveTps = phaseMoveCount / phaseActiveSeconds
```

- 总 TPS 包含思考与停顿，是默认比较口径。
- 活跃 TPS 排除阈值以上的无动作时间，必须显示“活跃 TPS（估算）”。
- `activeSeconds <= 0`、阶段为 skip 或 move 不完整时显示 `—`。
- O/P 可另外显示“起始停顿 + 执行 TPS”，但不得直接命名为精确识别时间。

### 6.4 停顿区间

默认 `pauseThreshold=250 ms`，用户可调。相邻事件为 `previousMove` 和 `currentMove` 时：

```text
pauseInterval = [previousMove.time + pauseThreshold, currentMove.time)
pauseMs = max(0, currentMove.time - previousMove.time - pauseThreshold)
```

阶段停顿时长通过 `pauseInterval` 与阶段时间段求交集分配。这样一个跨边界长 gap 只计算一次，且可以分摊到相邻阶段。

Solve 起点到第一 move、最后 move 到 solved 的无动作时间分别保存为 `startPause` 和 `endPause`。智能模式通常第一 move 即开始计时，因此 startPause 多为 0。

### 6.5 停顿率

```text
solvePauseRate = totalPauseMs / rawSolveMs
phasePauseRate = phasePauseMs / phaseDurationMs
```

- 以百分比显示，保留 1 位小数。
- 同时显示停顿次数、累计停顿、最长 gap。
- 阈值更改后所有停顿相关指标必须按 analyzerVersion 重算。
- 低于 500 ms 的阶段不单独强调停顿率，避免分母过小造成误导。

### 6.6 阶段起始停顿

`phaseEntryGap` 是前一阶段完成 move 到本阶段第一 move 的间隔。它可用作 Cross→F1、pair→pair、F2L→OLL、OLL→PLL 衔接指标。

UI 文案：

- “F2 开始前无 move 0.71 秒”。
- “OLL 阶段起始停顿比最近 20 次中位数长 0.24 秒”。

不得直接写“OLL 识别用了 0.71 秒”，因为其中可能包含调整握法、锁死或设备延迟。

### 6.7 转体与流畅度辅助指标

- `rotationCount`：来自 gyro 的稳定整体转体；无 gyro 显示“未记录”。
- `turnIntervalCv`：有效相邻 move 间隔的变异系数，仅作趋势辅助，不作为主评分。
- `burstCount`：连续快转后接长停顿的段数，可用于描述 stop-and-go，但不直接推断视线。
- 不生成单一“综合评分”，除非未来明确公开权重和校准样本。

## 7. 个人基线

### 7.1 基线数据集

默认取同一：

- puzzle=3×3。
- method=CFOP。
- Cross 颜色。
- 计数口径。
- 来源能力等级（完整智能 Solve 优先）。
- 最近 50 个完整且分析可靠/可参考的 Solve。

趋势建议至少需要 12 个样本；不足时只显示客观单次指标。

### 7.2 统计量

每个阶段和总体保存：

- sampleCount。
- median。
- P25 / P75。
- MAD（median absolute deviation）。
- 最近 5 / 12 / 50 的滚动值。

极端值不直接删除；DNF、数据不完整和人工排除使用明确状态。趋势默认使用中位数和分位数，避免一次爆炸成绩改变建议。

## 8. 提速建议引擎

### 8.1 输出结构

每条 `CoachingInsight` 包含：

- `insightId` 和 `ruleVersion`。
- `scope`：SOLVE / PHASE / TREND。
- `priority`：PRIMARY / SECONDARY / INFO。
- `metricKeys` 和实际值。
- `baselineWindow`、样本数和对比值。
- `evidenceRange`：move ordinal / time range。
- `messageKey` 与参数，不保存不可迁移的整句文本。
- `suggestedDrillId`。
- `confidence`。
- `dismissedAt`，允许用户隐藏不适合自己的建议。

### 8.2 首版规则

| 现象 | 必要条件 | 可显示结论 | 建议入口 |
|---|---|---|---|
| 停顿主导 | phasePauseRate 高于个人 P75 且 activeTPS 不低于个人中位数 90% | “这一段的主要差距来自无动作时间，不是转动速度” | 低速连续转动 / 节拍训练 |
| 执行速度主导 | activeTPS 低于个人 P25，pauseRate 不高 | “停顿不突出，执行速度低于近期水平” | 对应 case / 手法重复训练 |
| 步数偏高 | phaseMoves > 个人 P75+2，且局面识别可靠 | “这段比近期通常多 N 步” | 回放对比 / 公式变体 |
| Cross→F1 衔接慢 | F1 entry gap > max(个人 P75, 500 ms) | “Cross 后到第一对之间出现长间隔” | Cross+1 观察训练 |
| F2L 中段 stop-and-go | F2/F3 entry gap 或 pauseRate 连续偏高 | “中段两对之间的无动作时间较集中” | 慢拧不断流训练 |
| O/P 起始停顿高 | entry gap 高、执行 activeTPS 正常 | “阶段开始前等待偏长，公式执行速度正常” | OLL/PLL 识别训练 |
| O/P 执行偏慢 | entry gap 正常、activeTPS 低 | “识别后的执行速度低于近期水平” | case 定向重复 |
| 转体偏多 | gyro 可靠且 F2L rotationCount > 个人 P75 | “本次 F2L 稳定转体较多” | 无转体/后槽练习 |
| 波动偏大 | 最近 12 次 MAD 或标准差显著高于前 50 | “最近成绩波动扩大” | 稳定节奏组练习 |

### 8.3 相对阈值

“高/低”默认使用个人分位数，并同时满足最小差异，避免微小波动触发建议：

- 时间差至少 150 ms。
- pauseRate 差至少 5 个百分点。
- activeTPS 差至少 10%。
- move count 差至少 2 HTM。

具体阈值作为 analyzer 配置版本化，不写死在 UI。

### 8.4 建议排序

优先级分数仅用于排序，不展示为能力分：

```text
opportunityMs = max(0, observedPhaseMs - personalP25PhaseMs)
reliabilityWeight = confidence
repeatWeight = 1.0 + min(recentTriggerCount, 5) * 0.1
rankScore = opportunityMs * reliabilityWeight * repeatWeight
```

- 单次页选最高的一条 PRIMARY。
- 再显示最多两条 SECONDARY。
- 同一规则连续出现时合并为趋势建议，不刷屏。
- 不承诺“练完可提速 X 秒”；`opportunityMs` 只用于内部排序。

### 8.5 文案边界

允许：

- “F3 停顿率 31%，高于你最近 20 次的 18% 中位数。”
- “PLL 执行 TPS 接近近期水平，时间差主要出现在阶段开始后的 0.64 秒无 move。”
- “点击查看 8.22–8.86 秒区间，并开始 PLL 识别训练。”

禁止：

- “你没看下一对。”
- “你手法错误。”
- “AI 判断你必须换公式。”
- “达到职业水平还差 2.3 秒。”

## 10. 记录与统计

### 10.1 统计范围

所有 current / best / PB 必须带明确 scope：

- puzzle / category。
- session 或全部历史。
- tag（可选）。
- source（手动、智能魔方、蓝牙计时器）。
- penalty included。

默认 scope 为当前 3×3 session。筛选改变后重新计算该 scope 内的滚动序列，并在标题显示范围，避免把不同模式的纪录混为一谈。

### 10.2 记录首页层级

1. 当前水平：预测用时与区间、实战/执行 TPS、近期状态和可信度，算法遵循 11 文档。
2. 当前：最新 single、current ao5、current ao12。
3. 最佳：best single、best ao5、best ao12 和发生日期。
4. 趋势图：single / ao5 / ao12，可切换阶段时间、TPS、停顿率。
5. 一致性：中位数、标准差/MAD、总练习时间、计次。
6. 最近 Solve 列表。

“下一把 PB 阈值”的主要出现位置移到计时页的赛前阶段；记录页可在 PB 详情中保留计算解释和历史窗口，不再占据首页第三层。

P1 只强制 single、ao5、ao12；ao50 / ao100 作为 P2，但领域算法从一开始支持通用 N。

### 10.3 平均口径

沿用 06 文档：

- 结果使用 penalty-adjusted time。
- DNF 排在最差端。
- ao5、ao12 各剔除 1 个最好和 1 个最差。
- 通用 aoN 剔除两端各 `ceil(N × 5%)`。
- DNF 数超过可剔除的最差数量，则该平均为 DNF。
- 不足 N 条为 INSUFFICIENT，不显示 0 或 DNF。

### 10.4 精确比较与显示

内部平均不先四舍五入：

```text
AverageValue = VALID(sumAdjustedMs, divisor) | DNF | INSUFFICIENT
```

比较两个有效平均使用交叉相乘：

```text
a.sumMs * b.divisor < b.sumMs * a.divisor
```

PB 必须严格更小；显示相同但内部快 1 ms 仍可判 PB，并在详情说明比较使用原始毫秒。

### 10.5 current / best

- `current aoN`：以最新 Solve 结尾的 N 个结果。
- `best aoN`：scope 内所有连续 N 窗口的最小有效平均。
- 每个 best 保存窗口起止 solveId、剔除的最好/最差项和 analyzer/statVersion。
- 修改 penalty、恢复删除或移动 session 后，仅重算受影响位置开始的滚动窗口和 PB 链。

## 11. “下一把多少可以刷新纪录”

### 11.0 展示时机

计算核心不变，但主展示位置调整为计时前：scramble 已冻结，或智能魔方已匹配目标 scramble 后出现；进入 Running 后隐藏。本把目标生成后保持静态，详细状态机、专注模式和可访问性要求见 11 文档第 4 节。

### 11.1 用户文案

可能状态：

- `≤ 11.842 可刷新 ao5 PB`
- `下一把 DNF 也仍可刷新 ao5 PB`
- `本窗口已无法刷新 ao12 PB`
- `还需 4 次成绩才能形成 ao12`
- `暂无 ao5 PB`

阈值使用 **加罚后的最终成绩**。若下一把被判 +2，则 raw time 必须再少 2 秒。

### 11.2 计算定义

对 aoN：

1. 取 scope 中最近 `N-1` 个结果。
2. 取历史 `best aoN` 作为目标，排除将要形成的新窗口。
3. 定义候选最终成绩 `x`，组成 `window = recent + x`。
4. 使用与正式统计完全相同的 trimming / DNF 规则计算 `average(window)`。
5. 找到满足 `average(window) < bestAverage` 的最大整数毫秒 `x`。

不得为 ao5 写一套临时公式、为 ao12 再写另一套；必须调用同一个纯函数统计核心。

### 11.3 推荐实现

平均值对候选时间单调不减，可使用整数二分：

```text
if recent.size < N - 1:
    return NeedMore(N - 1 - recent.size)
if no historical best:
    return NoRecordYet
if evaluate(candidate = 0 ms) is not strictly better than PB:
    return ImpossibleThisWindow
if evaluate(candidate = DNF) is strictly better than PB:
    return DnfStillBreaksPb
binary search the largest x in [0, maxPredictableMs]
return NeedAtMost(x)
```

`maxPredictableMs` 默认 24 小时，仅为搜索上界；若达到上界仍可 PB，显示“任意有效成绩均可刷新”，不显示荒谬的大数字。

### 11.4 特殊情况

- 最近窗口已有 1 个 DNF：ao5/ao12 的下一把 DNF 通常会造成 2 个 DNF，从而平均为 DNF。
- 候选极快且成为被剔除的最好项时，阈值可能进入平台区；二分仍能正确处理。
- 候选极慢或 DNF 成为被剔除最差项时，平均可能不再变化。
- PB 为 DNF 或不存在：不显示数值阈值；先形成第一个有效平均。
- 阈值与 PB 比较使用精确分数，文案向下取整到可显示精度，保证用户达到显示阈值时一定能刷新。
- penalty 在 Solve 确认后才确定，预测页不得假设下一把一定无 +2。

### 11.5 PB 事件

每次确认或编辑 Solve 后生成/撤销：

- SINGLE_PB。
- AO5_PB。
- AO12_PB。
- 未来 AO50_PB / AO100_PB。

PB 事件保存旧值、新值、scope、窗口和触发 solveId。若后续编辑使 PB 失效，记录 `invalidatedAt`，不静默篡改历史通知。

## 17. 验收测试

### 17.1 分段 fixture

- 普通 Cross + 4 对顺序完成。
- X-cross、XX-cross。
- 两对同一 move 稳定完成。
- pair 完成、破坏、再次完成。
- OLL skip、PLL skip、带 AUF。
- gap 位于 F2、跨 F2/F3 边界。
- 非白 Cross。
- 人工修正边界后重算。

断言七段时间和等于 raw Solve；move 不重不漏；中心边界动作归属一致。

### 17.2 停顿 fixture

- gap 恰好等于 threshold：不算 pause。
- gap 比 threshold 多 1 ms：pause=1 ms。
- pause interval 跨阶段边界：交集之和等于总 pause。
- threshold 改变后 active TPS 和 pause rate 重算。
- skip/0 ms 阶段不除零。

### 17.3 平均与 PB fixture

- ao5 / ao12 普通窗口。
- +2 是最好、居中、最差三种位置。
- 0、1、2 个 DNF。
- 相同成绩和精确平均相同。
- 显示值相同、内部相差 1 ms。
- 编辑旧 Solve 导致多个后续窗口变化。
- 删除/恢复 Solve 后 PB 事件撤销/恢复。

### 17.4 下一把阈值 fixture

- 候选是剔除最好项。
- 候选是中间有效项。
- 候选是剔除最差项。
- DNF 仍可 PB。
- 即使 0 ms 也无法 PB。
- 尚无 PB / 不足 N-1 条。
- 返回阈值的 `x` 可 PB，而 `x+1 ms` 不可 PB。
- 阈值只在 scramble 冻结/匹配后到 Running 前显示，本把显示期间保持静态。

### 17.5 建议 fixture

- active TPS 正常但 pauseRate 高，只触发停顿建议。
- pauseRate 正常但 active TPS 低，只触发执行建议。
- 样本少于 12 不触发趋势建议。
- confidence 低不触发确定性建议。
- 每条建议能定位到 evidenceRange。
- 同类建议合并且最多一主两次。

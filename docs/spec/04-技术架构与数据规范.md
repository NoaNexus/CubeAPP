# 04. 技术架构与数据规范

## 1. 架构目标

- 在无网络权限的 Android APP 内完成全部核心工作。
- 让 BLE、计时、魔方状态、三维渲染和数据库互相解耦。
- 原始事实可追溯，分析算法可升级、可重跑。
- 单个渲染器或分析器失败时，不损坏计时和历史数据。
- 允许从协议验证小应用逐步演进，不先建过度抽象的平台。

## 2. 建议技术栈

| 领域 | 选择 |
|---|---|
| 语言 | Kotlin |
| UI | Jetpack Compose + Material 3 基础能力，自定义视觉 token |
| 最低系统 | minSdk 26；compileSdk / targetSdk 使用开发时稳定最新版 |
| 并发 | Coroutines、Flow、StateFlow |
| 依赖注入 | Hilt 或简洁的构造注入；首个协议验证阶段可不引入 Hilt |
| 数据库 | Room / SQLite |
| 设置 | DataStore |
| 序列化 | kotlinx.serialization |
| 蓝牙 | Android BluetoothGatt |
| 三维 | 本地 WebView + WebViewAssetLoader + 未修改 cubing.js |
| 图表 | Compose Canvas 优先，避免引入大型图表依赖 |
| 测试 | JUnit、kotlinx-coroutines-test、Room 内存库、Compose UI Test |

不声明 INTERNET 权限。所有网页资源、字体、JavaScript 和样式随 APK 打包。

## 3. 运行时分层

~~~mermaid
flowchart LR
    V["V10 AI"] --> B["BLE 传输与解密"]
    B --> E["规范化事件总线"]
    E --> C["魔方状态引擎"]
    E --> S["Solve 记录器"]
    E --> O["朝向轨迹"]
    C --> U["Compose UI"]
    C --> R["三维渲染桥"]
    O --> R
    S --> D["Room / 文件存储"]
    D --> A["CFOP 分析器"]
    A --> D
    D --> U
    U --> R
~~~

边界规则：

- BLE 层不判断 CFOP。
- 三维层不维护唯一魔方状态，也不直接写数据库。
- 分析器只读取已完成 Solve 的快照，不控制计时。
- UI 不直接拼接 GATT 指令。
- 计时使用系统单调时钟，不使用墙上时间计算耗时。

## 5. 统一事件模型

### 5.1 原始层

RawBleFrame：

| 字段 | 说明 |
|---|---|
| sessionId | 本次连接会话 |
| direction | RX 或 TX |
| characteristic | 特征 UUID |
| receivedElapsedNanos | 本地单调到达时间 |
| wallClockUtc | 仅用于诊断定位 |
| encryptedBytes | 原始字节；仅调试模式保留 |
| firmware / profile | 解析上下文 |

原始包默认只在内存环形缓冲中保留。用户开启诊断后，最多保留最近 20 次 Solve 或设定容量；普通成绩不需要永久保存所有加密包。

### 5.2 规范化层

统一事件是带时间的密封类型：

- DeviceInfoEvent。
- BatteryEvent。
- FaceletSnapshotEvent。
- MoveEvent。
- OrientationEvent。
- SyncGapEvent。
- ConnectionEvent。

MoveEvent 至少包含：

| 字段 | 说明 |
|---|---|
| sequence | 设备或适配层序号 |
| move | 规范 move，例如 R、U2、F prime |
| deviceTime | 若协议提供则保留 |
| receivedElapsedNanos | 本地到达时间 |
| estimatedMoveElapsedNanos | 时间对齐后的动作时刻 |
| stateHashAfter | 应用动作后的状态摘要 |
| flags | 乱序、补发、重同步前后等 |

OrientationEvent 包含归一化四元数 x、y、z、w、校准 profile 版本、到达时间和质量标记。

### 5.3 派生层

DerivedAnalysis：

- analyzerVersion。
- inputDigest。
- phaseSegments。
- metrics。
- anomalies。
- confidence。
- userCorrections。

当 analyzerVersion 或 inputDigest 变化时重新计算。用户修正与自动结果分开保存，不覆盖原自动值。

SkillEstimate 是 DerivedAnalysis 之上的可重建缓存：只读取已确认 Solve 与带版本分析，不覆盖任何事实。它按 scope 保存长期稳定状态、近期状态、协方差、预测区间、回测状态和 modelVersion；算法与降级规则以 11 文档为准。

## 6. 核心数据实体

### 6.1 公式与训练

| 实体 | 关键字段 |
|---|---|
| AlgorithmSet | id、method、name、presetVersion、source |
| CubeCase | stableId、stage、number、names、canonicalState、orientationRule、sortOrder |
| AlgorithmVariant | id、caseId、notation、normalizedMoves、sourceType、verified、userOrder |
| UserCaseState | caseId、preferredVariantId、favorite、masteryBox、dueAt、notes、updatedAt |
| Tag | id、name、colorToken、createdAt |
| CaseTagCrossRef | caseId、tagId |
| TrainingAttempt | id、caseId、variantId、mode、result、recognitionMs、executionMs、occurredAt、solveId |

预设表和用户覆盖表分离。stableId 例如 cfop.oll.21，不因显示名称或排序变化而改变。

### 6.2 计时与复盘

| 实体 | 关键字段 |
|---|---|
| SolveSession | id、name、puzzle、createdAt、archived |
| Solve | id、sessionId、scramble、startedElapsed、endedElapsed、startedWallClock、durationMs、penalty、source、completeness、deviceProfileId、notes |
| SolveTagCrossRef | solveId、tagId |
| MoveEventEntity | solveId、ordinal、sequence、moveCode、moveTimeNanos、receiveTimeNanos、stateHash、flags |
| OrientationTrack | solveId、formatVersion、sampleRateHint、calibrationId、binaryBlob、checksum |
| FaceletCheckpoint | solveId、ordinal、elapsedNanos、state、reason |
| PhaseSegment | solveId、analyzerVersion、stage、startNanos、endNanos、confidence、source |
| SolveMetric | solveId、analyzerVersion、metricKey、numberValue、unit、scope |
| AnalysisAnomaly | solveId、kind、startNanos、endNanos、severity、details |
| SkillEstimateSnapshot | scopeKey、metricKey、modelVersion、stableMean、formMean、covariance、sampleCount、status、inputDigest |
| ForecastOutcome | forecastId、solveId、scopeKey、metricKey、generatedAt、quantiles、actualValue、nonconformityScore、excludedReason |
| SkillModelConfig | modelVersion、configVersion、parameters、backtestSummary、createdAt |

durationMs 始终保存原始耗时。最终显示：

- NONE：durationMs。
- PLUS_TWO：durationMs + 2000。
- DNF：DNF，同时保留 durationMs 用于复盘。

SkillEstimateSnapshot 不是唯一事实源，必须能从 Solve、MoveEvent、DerivedAnalysis 和显式用户排除记录重建。ForecastOutcome 必须先保存预测、Solve 确认后再写实际值，防止回测读取未来数据。

### 6.3 设备与设置

| 实体 | 关键字段 |
|---|---|
| DeviceProfile | id、displayName、addressHint、firmware、protocolVersion、capabilities、lastSeenAt |
| CalibrationProfile | id、deviceProfileId、referenceQuaternion、axisMapping、handedness、createdAt、verified |
| AppSetting | 使用 DataStore；Cross 颜色、记号、阈值、主题、反馈选项 |
| PresetManifest | presetVersion、contentHash、installedAt、sourceNotice |

addressHint 可能是 Android 扫描地址、设备名后缀或用户确认的 MAC。UI 不应把内部来源差异展示为三个重复设备。

## 7. 四元数轨迹存储

不为每个高频样本建立一条 Room 行。每个 Solve 使用一个或少量分块 BLOB：

- 4 字节格式标识，例如 CTQ1。
- formatVersion、时间基准和样本数。
- 每个样本保存变长时间差。
- 归一化 x、y、z、w 量化为四个有符号 16 位整数。
- 每秒或每个分块写入绝对时间锚点。
- 分块带 CRC32 或 SHA-256 摘要。

50 Hz 时，15 秒原始量级约十几 KB；即使保留 10,000 次 Solve 也需要容量策略。默认：

- 前台实时渲染可接收设备原始频率。
- 持久化最高 50 Hz。
- 相邻姿态变化低于阈值时可稀疏采样，但动作前后保留关键帧。
- 用户可选择仅保留 move、不保留历史手持朝向。

导出备份时可再用 ZIP Deflate 压缩，不依赖私有压缩服务。

## 8. 时间基准

必须区分：

- wallClockUtc：用于按日期显示，可能被用户或系统校时改变。
- elapsedRealtimeNanos：用于计时和事件排序，单调递增。
- deviceTime：设备包中若有相对时间，仅用于估计动作发生时刻。

连接建立后，用一段滑动窗口估计 deviceTime 到本地 elapsed 时间的偏移；发生回绕、跳变或重连时新建 epoch。任何耗时指标都不得直接用两次 wall clock 相减。

## 9. 计时状态机

~~~mermaid
stateDiagram-v2
    [*] --> Idle
    Idle --> Holding: 手动按住
    Holding --> Ready: 达到准备阈值
    Ready --> Running: 松手
    Idle --> Scrambling: 智能模式
    Scrambling --> Inspection: 状态匹配
    Inspection --> Running: 第一 move
    Running --> Stopped: 手动停止或 solved
    Running --> Syncing: move 空洞或断连
    Syncing --> Running: 恢复且仍未 solved
    Syncing --> Stopped: 已 solved 或用户停止
    Stopped --> Confirmed: 保存
    Stopped --> Idle: 放弃
    Confirmed --> Idle
~~~

状态迁移由单一 reducer 处理。UI、BLE 回调和生命周期事件只能提交 action，不能各自直接修改计时布尔值。

## 10. BLE 连接状态机

    Idle
      → PermissionRequired
      → Scanning
      → Connecting
      → DiscoveringServices
      → Handshaking
      → RequestingState
      → Ready
      → Reconnecting
      → Error

要求：

- 每次 GATT 操作串行排队，并有超时。
- Android GATT 回调转为 Flow 前先做线程安全排序。
- 连接断开后关闭旧 GATT，再创建新实例。
- 前台计时中采用有限快速重连；非计时页采用温和退避。
- 首版不建立常驻后台服务；APP 退到后台时按计时状态决定是否短时保持连接。

## 11. 三维渲染边界与安全

### 11.1 加载策略

- 使用 WebViewAssetLoader 从受控 HTTPS 样式本地地址加载。
- 禁止任意外链导航。
- 关闭 allowFileAccess、allowContentAccess 和不必要的混合内容。
- 不启用通用 JavaScript 原生对象桥。
- 优先使用 WebMessagePort / postWebMessage 传输少量、带版本的 JSON 消息。
- 只接受固定 origin 和 schema；未知字段忽略，非法消息记录后拒绝。

### 11.2 消息协议

原生 → 渲染器：

- Initialize(themeTokens, colorProfile, reducedMotion)。
- SetCubeState(facelets, sequence)。
- ApplyMove(move, sequence, durationMs)。
- SetOrientation(quaternion, sequence)。
- SetCameraMode(mode)。
- SeekReplay(timeMs, state, orientation)。

渲染器 → 原生：

- Ready(rendererVersion)。
- FrameApplied(sequence)。
- CameraChanged(cameraState)。
- RenderError(code, safeDetails)。

业务层不依赖 FrameApplied 才更新逻辑状态；它只用于渲染积压监控。

### 11.3 降级

WebView 崩溃或不可用时：

- 计时和 BLE 继续。
- 显示由 Compose Canvas 绘制的静态二维局面。
- Formula 仍能以 token 单步浏览。
- 用户可重载三维视图，失败信息进入诊断。

## 12. 备份格式

建议扩展名：

    .cubetrace.zip

内容：

    manifest.json
    user-data.jsonl
    move-events.bin
    orientation/
    presets/manifest.json
    attachments/
    checksums.sha256
    licenses/

manifest 必含：

- formatVersion。
- appVersion。
- exportedAtUtc。
- schemaVersion。
- presetVersion。
- counts。
- optionalFeatures。
- 每个文件的大小和摘要。

导入步骤：

1. 复制到应用私有临时目录。
2. 验证 ZIP 路径，拒绝路径穿越和超大解压比。
3. 校验摘要、格式版本和可用空间。
4. 解析到临时数据库。
5. 展示新增、合并、冲突和跳过数量。
6. 用户确认后单事务合并。
7. 保留导入前自动快照，直到用户完成一次正常启动。

## 13. 数据迁移

- Room migration 必须显式编写并测试，不启用 destructiveMigration。
- 每个发布版本保留前两个公开版本的升级测试。
- 预设内容升级按 stableId 合并；新预设直接加入，修改预设更新 preset 层，不动 UserCaseState。
- 分析结果可删除重算，但原始 Solve、MoveEvent、OrientationTrack 和用户修正不可丢失。
- 数据库打开失败时进入恢复模式，允许导出原数据库和诊断，不自动清空。

## 14. 线程、背压与性能

- BLE 回调只做最小复制和排队，不做三维或数据库重活。
- move 是不可丢事件，使用有界但足够大的顺序 channel；溢出即标记 gap 并重同步。
- gyro 是可降采样事件，UI 最多按屏幕刷新率消费；持久化最多 50 Hz。
- Room 写入按 Solve 小批量事务，不为每个 gyro 样本提交事务。
- 分析在 Solve 完成并持久化后运行，可取消、可重试。
- 公式卡片缓存二维图；列表不嵌入 WebView。

## 15. 安全与隐私

- 应用没有网络发送路径。
- AES key、IV 和设备地址只存在应用私有存储和内存；诊断导出默认遮蔽完整地址。
- 不记录用户其他附近蓝牙设备的长期清单。
- BLE 写入使用 opcode 白名单和固定长度校验。
- 备份不加密是默认的透明选择；如以后增加密码备份，使用 Android 支持的标准 KDF 和 AEAD，不自创算法。
- Release 构建关闭详细原始包日志，只有用户显式开启诊断才短时记录。

## 16. 依赖准入

每个第三方依赖进入项目前记录：

- 名称、版本、源码地址和许可证。
- 直接或传递依赖。
- 是否修改过源码。
- 是否进入 APK。
- 对应 notice 和 source 获取方式。
- 是否需要网络、反射、原生库或额外权限。

优先使用 AndroidX、Kotlin 官方库和少量经过审查的依赖。不要为了一个小组件引入整套联网 SDK。

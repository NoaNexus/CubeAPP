# 方迹 CubeTrace：离线魔方公式与复盘 APP 设计文档

> 文档版本：1.2
> 状态：可进入原型与协议验证  
> 目标平台：Android 8.0 及以上  
> 目标设备：魔域威龙 V10 AI  
> 首版方法：3×3 CFOP  
> 工作名称：“方迹 CubeTrace”，后续可更名

## 1. 文档目的

这套文档把产品范围、交互、视觉、数据、蓝牙协议、三维跟踪、CFOP 复盘、智能成绩分析、赛前纪录目标、赛后即时反馈、当前水平估计、滚动平均与纪录预测、开源合规、验收方法和开发交接统一为一份可执行基线。后续新建 Codex 任务时，应先阅读本目录，再开始写代码。

本套文档使用独立的魔方 APP 工作区，与“出差记录 APP”完全隔离。项目根目录为：

    C:\CodexProjects\CubeAPP

设计文档位于：

    C:\CodexProjects\CubeAPP\docs\spec

后续 Android 与 Git 工程直接在项目根目录初始化，并保留 docs\spec；不得再把魔方代码或文档放进“出差记录 APP”工程。

## 2. 已冻结的核心决策

| 主题 | 决策 |
|---|---|
| 产品定位 | 自用优先、可离线分享给几十位朋友的 CFOP 学习与实拧复盘工具 |
| 平台 | Android 原生，首版不做 iOS、网页端和桌面端 |
| 网络 | 所有核心功能离线；应用不申请 INTERNET 权限 |
| 智能魔方 | 首版只支持魔域 V10 AI，不抽象成“所有品牌都能连接” |
| 公式范围 | 41 个 F2L、57 个 OLL、21 个 PLL，共 119 个预设 case |
| 主导航 | 公式、训练、计时、记录四个底部入口；设备和设置为上下文入口 |
| 三维显示 | 原生 BLE 与状态机；本地受限 WebView 承载 cubing.js 三维渲染 |
| 数据存储 | Room / SQLite 为唯一事实源；支持完整离线备份与恢复 |
| 复盘原则 | 保存原始事件、规范化事件和可重算分析结果；分析器带版本号和置信度 |
| 水平估计 | 完全离线、长期水平与近期状态分离、异常值稳健降权、预测带区间和回测降级 |
| 开源策略 | 若复用 csTimer 或 Twisty Timer 的 GPL 代码或数据，整套 APP 采用保守的 GPL-3.0-only |
| 分发 | 签名 APK + 对应源码包 + 许可证与构建说明；不要求公开上架 |
| 首个里程碑 | 先做 V10 AI 协议验证页，真实硬件通过后再扩展完整产品 |

## 4. 需求优先级定义

| 标记 | 含义 |

| P1 | 首个可分享版本必须具备 |

| 非目标 | 本轮明确不做，除非重新评审范围 |

## 5. 统一术语

| 术语 | 本文含义 |
|---|---|
| case | 一类可识别的魔方局面，例如某个 OLL 或 PLL |
| 公式变体 | 同一 case 的一条可执行转动序列 |
| 首选公式 | 用户对一个 case 当前选择的默认变体 |
| move | 单层、宽层、夹层或整体转体的一个规范化动作 |
| 原始事件 | 设备发来的字节、到达时间及连接上下文 |
| 规范化事件 | 解密、解析并转为统一坐标和记号后的 move、状态或四元数 |
| 分析结果 | CFOP 分段、TPS、停顿等可由事件重算的数据 |
| Move Rail | 贯穿实时跟踪与复盘的“转层轨道”，把动作、停顿和 CFOP 阶段放在同一时间轴上 |
| 当前水平 | 基于同 scope 历史与近期数据估计的下一次可复现表现分布，不等同于 PB 或绝对能力评级 |
| 实战 TPS | move 数 ÷ raw Solve time，包含停顿 |
| 执行 TPS | move 数 ÷ 排除规则停顿后的活跃时间，必须标注“估算” |

## 6. 变更规则

- 硬件实测结果优先于第三方协议实现和本文假设。
- 产品范围、协议安全写入白名单、数据库破坏性迁移、许可证变更，必须先更新文档再改代码。
- 预设公式内容必须有来源、校验状态和版本号；用户自己的公式不得被升级覆盖。
- 所有分析结果都必须能从保留的原始或规范化事件重新生成。
- 新增智能魔方品牌属于新版本范围，不得通过在 V10 AI 代码中堆积临时分支实现。

# 08. 测试验收与迭代路线图

## 1. 总体策略

开发以可验收的纵向切片推进，不按“先写所有数据层、再写所有页面”的方式堆积。每个里程碑都必须：

- 有可安装 APK。
- 有自动化测试。
- 有真机验证记录。
- 能在飞行模式运行。
- 不破坏前一里程碑数据。
- 记录未通过项和风险，不以演示视频代替验收。

## 2. 里程碑

### M0：V10 Lab 协议验证

范围：

- 新建干净 Android 工程。
- 蓝牙权限、扫描和连接。
- MAC 来源、AES key / IV 派生和协议解密。
- 设备信息、电量、facelet、move、gyro。
- 简单魔方状态和四元数三维显示。
- 安全写入白名单。
- 脱敏诊断导出。

退出条件：

- 05 文档第 16 节全部通过。
- 20 次完整复原最终状态一致。
- 三轴校准与 q / -q 连续性通过。
- 真实设备证据归档。

若没有真机，最多完成“待真机验证”，不得宣布 M0 完成。

### M1：产品骨架与公式库

范围：

- 四入口导航与视觉 token。
- CubeEngine、记号 parser 和公式 validator。
- Room schema 与迁移测试。
- 119 个 case 的数据管线和初始预设。
- 公式首页、详情、编辑和本地三维演示。
- 许可证、第三方清单和来源账本框架。

退出条件：

- 119 个 stableId 唯一。
- 所有预设公式自动校验；人工抽检记录完成。
- 公式列表性能达标。
- WebView 在禁网、错误和重建场景可降级。

### M2：训练与手动计时

范围：

- 识别训练、执行训练和五级复习箱。
- 手动计时、观察、+2、DNF、session 和平均值。
- 记录首页与基础趋势。
- 备份格式第一版。

退出条件：

- 训练队列和掌握度规则有确定性测试。
- 计时横竖屏、前后台和误触场景通过。
- ao5 / ao12 / ao100 的 DNF / +2 测试通过。
- 备份可在另一台设备往返恢复。

### M3：V10 AI 产品化连接

范围：

- 把 M0 协议模块接入训练和计时。
- Scramble 状态校验、第一 move 启动、solved 停止。
- 设备面板、自动重连、重同步和用户校准。
- 实时三维、Move Rail 实时模式。
- OrientationTrack 压缩持久化。

退出条件：

- 100 次智能计时无未提示的状态错位。
- move 逻辑 P95 延迟达标。
- 人为断连和序号 gap 有明确降级。
- 长时间 gyro 记录不造成内存持续增长。

### M4：CFOP 复盘与统计

范围：

- 稳定谓词分段。
- Cross / F2L / OLL / PLL 指标，并按 10 文档细分为 C / F1 / F2 / F3 / F4 / O / P。
- F2L slot 进度、skip、regression 和异常。
- 回放 seek、速度、Move Rail 和人工边界修正。
- 置信度与分析器版本。
- OLL / PLL case 匹配。
- 总体及分阶段 time、move、总 TPS、活跃 TPS、停顿率和转体。
- current / best single、ao5、ao12、PB 事件和下一把 PB 阈值。
- 个人基线与带证据区间的规则式提速建议。
- 完整智能 Solve 的赛后关键指标行与“深度分析”主按钮；手动和 gap 数据按 11 文档降级。
- scramble 冻结/匹配后且计时开始前显示静态 ao5 / ao12 本轮目标。
- CTSS-1 总体当前水平：长期/近期双状态、稳健异常降权、预测区间、样本门槛和基线回退。
- 七段当前水平与自适应区间校准按 11 文档分 P1-C / P2 落地，不阻塞先完成可靠总体模型。

退出条件：

- 06 文档测试语料全通过。
- 带 gap 的 Solve 不输出伪精确指标。
- 修改 analyzerVersion 可重算且不覆盖原始数据。
- 真实 Solve 抽检中阶段边界可解释。
- 七段时间和等于 raw Solve time，边界 move 不重不漏。
- 下一把 PB 阈值满足：返回的 `x` 可严格刷新，而 `x+1 ms` 不可刷新。
- 少于 12 个可靠样本时不生成趋势建议；每条已生成建议可定位到指标和 Move Rail 证据。
- 赛后摘要在分析未完成时仍可确认成绩；手动 Solve 不显示虚构的 HTM/TPS。
- PB 目标只在 scramble 完成后到 Running 前可见，进入 Running 后隐藏且本把不跳数。
- 少于 5 个有效样本不显示数值水平；模型状态可从事实重放确定性重建。
- rolling-origin 回测无未来数据泄漏；CTSS-1 不优于最近 12 次稳健基线时自动回退。
- 满足足量样本后，80% 区间覆盖率未达 11 文档门槛时不得标“可靠”。

### M5：0.1.0 小圈子发布

范围：

- 性能、无障碍、错误文案和恢复页。
- 旧版覆盖升级与完整备份。
- APK、源码、许可证和 SHA-256。
- 三档 Android 设备回归。

退出条件：

- G2 全部通过。
- 无 P0 / P1 缺陷。
- 发布包可在干净环境构建。
- 签名材料完成双份备份。

## 3. 测试分层

| 层 | 重点 |
|---|---|
| 纯单元测试 | move parser、cube state、AES 测试向量、四元数、CFOP 谓词、平均值 |
| 属性测试 | 随机序列 + inverse 回到原状态、四元数归一化、备份往返 |
| 数据库测试 | DAO、事务、升级迁移、用户覆盖不被预设覆盖 |
| 协议回放测试 | 保存的脱敏 BLE fixture，无硬件复现 parser 和 gap |
| 集成测试 | BLE fake → recorder → Room → analyzer → UI state |
| Compose UI | 导航、字体放大、计时状态、异常和 TalkBack 标签 |
| WebView 契约 | 消息 schema、origin、重载、sequence 追赶和降级 |
| 真机测试 | GATT、延迟、生命周期、设备差异、功耗 |
| 发布测试 | APK 安装、覆盖升级、源码构建、离线性和权限 |

## 4. 自动化重点

### 4.1 CubeEngine

- 18 个基本外层 move 的正逆和 180°。
- 同一 face 做 4 个 quarter turn 回到原状态。
- 随机 1,000 组序列与 inverse。
- facelet ↔ cubie 往返。
- 非法颜色计数、奇偶和方向状态拒绝。
- stateHash 稳定。

### 4.2 公式

- 所有支持 token 的 parser golden tests。
- Unicode prime、普通 apostrophe、全角空格和小写宽层别名。
- 错误位置准确。
- 119 个 case 和全部预设变体校验。
- 缩略图快照只作为视觉回归，局面 hash 才是逻辑真值。

### 4.3 四元数

- 四个 int32 little-endian 读取。
- 2 的 30 次方缩放。
- 归一化与非法长度。
- q / -q 连续输入。
- SLERP 端点和近共线。
- 每种 axisMapping 的正负 90°。
- reference 校准和 sceneCorrection 顺序。

### 4.4 时间与统计

- 墙上时钟跳变不影响 duration。
- device timestamp 回绕和重连 epoch。
- +2 / DNF 排序。
- ao5 / ao12 / ao100 剔除数量。
- current / best average 使用未舍入值比较。
- 下一把 ao5 / ao12 PB 阈值覆盖候选被剔除为最好、居中、最差和 DNF 四类。
- 赛前目标状态覆盖 scramble 未完成、匹配、Ready、Inspection、Running 和后台统计重算。
- 阶段零时长 skip。
- pauseThreshold 边界值。
- pause interval 跨阶段边界时，各阶段交集之和等于总体 pause。
- X-cross、同时完成 pair 和 pair regression 的 F1–F4 边界。
- CTSS-1 覆盖异常值降权、连续改善响应、长间隔不确定性增长、+2/raw、DNF、缺失 phase 和重放确定性。
- 水平回测覆盖 rolling-origin 无泄漏、基线比较、50%/80% 覆盖率和 FALLBACK 状态。

### 4.5 备份

- 空库和 10,000 Solve。
- 未知可选字段向前兼容。
- checksum 错误。
- ZIP 路径穿越。
- 超大解压比。
- 中途空间不足。
- stableId 冲突。
- 导入失败后原数据库不变。

## 5. 真机矩阵

### 5.1 Android

至少：

| 档位 | 目标 |
|---|---|
| 低版本 | Android 8–10，验证旧权限和 WebView |
| 主力 | 用户日常手机，记录型号、Android 和厂商系统 |
| 新版本 | 当前较新 Android，验证附近设备权限和后台限制 |

最好覆盖一个国产深度定制系统和一个接近原生系统。每次发布不要求拥有大量手机，但主流程必须在三档真机通过。

### 5.2 V10 AI

记录：

- 完整商品型号。
- 广播名。
- 固件。
- 购买批次或可识别版本。
- 服务和特征 UUID。
- move / gyro 消息长度与频率。

若朋友的同型号固件不同，把它作为新的 DeviceProfile 验证，不直接当成已支持。

## 6. 协议耐久测试

- 连接 / 断开循环 50 次。
- 前后台切换 30 次。
- 横竖屏切换 30 次。
- 连续连接 60 分钟。
- 快速 move 500 次。
- 完整 Solve 100 次。
- 蓝牙中途关闭 / 打开。
- 设备被另一 APP 抢占。
- 手机锁屏后短时恢复。
- 电量低时行为。

记录：

- 成功率。
- 连接耗时中位数 / P95。
- move 延迟中位数 / P95。
- sequence gap 数。
- 自动恢复成功率。
- gyro 有效采样率。
- 内存、CPU 和电量趋势。

## 7. UI 验收矩阵

- 320 dp 窄屏。
- 360 / 390 / 411 dp 常见宽度。
- 横屏。
- 系统字体 100%、130%、200%。
- 中文和公式混排。
- TalkBack。
- 深色系统下首版浅色策略是否一致。
- 降低动态效果。
- 色觉辅助标签。
- 无 WebView 或 WebView renderer process 崩溃。
- 未授权蓝牙、蓝牙关闭、未连接、待校准、同步中。

截图回归聚焦：

- case 卡片。
- 大计时各状态。
- Move Rail。
- 阶段表。
- 设备状态胶囊。
- 备份冲突预览。

## 8. 缺陷级别

| 级别 | 定义 | 发布要求 |
|---|---|---|
| P0 | 数据丢失、错误 BLE 写入、计时或状态系统性错误、无法启动 | 立即阻断 |
| P1 | 核心闭环无法完成、未提示的状态错位、备份不可恢复、严重无障碍问题 | 阻断 |
| P2 | 有替代路径的功能错误、明显性能或视觉问题 | 评审后可延期 |
| P3 | 文案、轻微布局或低频边缘问题 | 可进入后续版本 |

“偶发”不降低数据损坏和错误设备写入的严重度。

## 9. 每个 PR / 任务的完成定义

- 需求 ID 和验收项明确。
- 不修改范围外文件。
- 新逻辑有自动化测试。
- UI 有正常、加载、空、错误和恢复状态。
- 数据结构有迁移或明确说明无需迁移。
- 新依赖完成许可证记录。
- 无新增网络权限或任意 BLE 写入。
- 真机相关功能附设备与结果。
- 文档与实际行为同步。
- 构建、单元测试和相关 UI 测试通过。

## 10. 发布检查

### 数据

- [ ] 从上一公开版覆盖升级成功。
- [ ] 升级前后记录数和关键摘要一致。
- [ ] 完整备份在第二台设备恢复。
- [ ] 不足空间和损坏备份安全失败。

- [ ] 扫描、授权、连接、校准、重连、忘记设备。
- [ ] 100 次智能 Solve 验证。
- [ ] move gap 与断连演练。
- [ ] Release 包无 raw write。

### 产品

- [ ] 公式 → 训练 → 计时 → 复盘闭环。
- [ ] 119 个 case 内容清单冻结。
- [ ] 统计定义帮助页一致。
- [ ] 飞行模式全部核心功能。

### 发布

- [ ] versionCode / versionName。
- [ ] release keystore 备份。
- [ ] APK 与 source.zip 同 commit。
- [ ] 第三方清单和公式来源账本。

## 11. 后续版本候选

只有 0.1.0 稳定后再评估：

- 具体 F2L case 的自动识别与训练推荐。
- 色中 Cross 分析。
- 深色主题。
- 更多智能魔方协议。
- 自定义方法集，例如 Roux。
- 结构化 CSV / JSON 统计导出。
- 局域网内可选的点对点备份。

云同步、排行榜和 AI 教练不自动进入路线图，除非产品定位重新评审。

# Implementation status

本文件把“已经写入工程”和“需要真实设备或内容审校才能宣称完成”分开，避免把代码存在误读成硬件验收通过。

## 已写入工程

- 四入口 Compose 工作台、浅色视觉 token、设备状态胶囊、Case 卡片、Move Rail、统计趋势和设置弹层。
- 公式 token parser：外层面、prime、2、宽层别名、夹层、转体、括号分组与重复次数错误定位。
- 54 facelet CubeState、局面 hash、scramble、程序生成贴面图和原生 Canvas 等距三维演示。
- SQLite schema：case / variant / user state / solve / move event / training attempt；当前 schema version 15，新增 Solve 起止 facelet/sequence、Cross 面和动作设备时间/单调接收时间/时间质量，并保留旧数据的显式迁移。
- DataStore 设置、掌握度五级复习箱、手动计时、+2 / DNF、ao5 / ao12、离线 ZIP 备份。
- V10 AI：BLE 权限抽象、广播粗筛、GATT 服务发现、串行操作队列、公开协议字段解码、AES 包装、四元数连续性和安全命令白名单。
- 离线成绩分析：分析器 2.1.0 采用严格 ReplayValidation 校验打乱、起始检查点、动作解析/序列、终点检查点和最终还原；CFOP 阶段不固定使用记录中的 Cross 面，而是同时评估六个底色，选择能形成最强独立 F2L→OLL→还原证据链的底色，再按该底色首次成立的十字、F1–F4 槽位、顶面统一（OLL）和整体还原（PLL）记录边界。阶段后来被临时改变不再被误报为分析失败或降置信度。A5 快速连转包按实际动作数校验序号距离，并为新记录的包内动作恢复逐步序号，旧版同包同序号成绩也可重算；若仅漏传一个设备序号，则只在 12 种合法 90° 面转中存在唯一候选且该候选能精确连接已保存起止局面时，于复盘内临时补全并降低置信度，原始数据库不改写；推定时间不计入 TPS、停顿率或 CTSS-1。历史记录复盘显示识别底色及当次七段时间、占比、步数、实战/执行 TPS、停顿率和最长停顿，并按个人基线生成最多一主两次的可解释建议；建议现在可附带通过阶段目标校验且局面唯一匹配的 OLL/PLL 参考公式、起手三步和明确标注为练法而非手指识别的指法提示。复盘可把原打乱作为全新一轮重新练习，未确认成绩由用户明确选择保存或放弃，新一轮使用独立记录 ID。V10 A5 在协议层进入无界动作事件流，Compose 不参与动作事实记录；智能打乱按同面净转角和精确局面接受 U2←U' U'、R←R' R' R' 等等效路径，跨面错误仍进入撤销流程。CTSS-1.1 排除无法可靠恢复的不完整、gap、含推定时间或含不可用阶段的样本，并通过更低的状态噪声和更强的异常降权降低单把异常对可见水平的影响，满 12 个可靠样本后才输出近期提速或回落。CTSS 与历史复盘已移到后台计算并复用缓存，记录列表使用懒加载；最近 12 次有效成绩趋势按成绩序号横向等距，同时保留真实日期时间标签。智能打乱匹配后冻结 ao5/ao12 PB 目标，并保持到 Running 前；设置可关闭提示。无依赖 JVM 回归入口目前覆盖 39 项重放、阶段、建议、等效打乱和 PB 边界检查。

## 当前明确的产品边界

- `PresetCatalog` 已内置 41 F2L / 57 OLL / 21 PLL 的完整参考目录；公式统一按黄顶蓝前解释，canonicalState 由公式逆序生成，来源记录在 `docs/provenance/formulas.yml`。
- V10 AI 适配层是代码实现，不是 G0 真机证据。真实广播、固件、MAC、AES 包、facelet 顺序、move gap、四元数轴向与校准仍需设备记录。
- 手动 Solve 没有动作事件时，复盘页会明确显示“没有动作事件”，不输出伪造的 CFOP 阶段时间。
- 旧版历史成绩没有动作事件时继续保留并只参与基础成绩统计；不会被当作完整智能样本，也不会进入 CTSS-1 或伪造七段指标。
- 旧版有动作但没有起止检查点/序列证据的记录继续保留，可显示可靠总时间或已记录动作数，但 CFOP 分段降级为不可用；分析结果版本为 `2.0.0`，后续可按新规则重算。
- CTSS-1.1 当前为可重建的本地 P1 版本：达到 5 次完整智能成绩后显示数字区间，12 次以后才评价近期状态，30 次以后根据滚动误差与 80% 区间覆盖率决定“可靠”或回退到稳健基线；自适应保形校准、持久化快照和后台重建仍属于后续切片。
- 三维演示只负责本地展示，不持有业务 CubeState；BLE move 事实现在已从 V10 解析成功点直接送入计时记录，orientation 仍需真机报告验证轴向、延迟和校准质量后才宣称 G0 完成。
